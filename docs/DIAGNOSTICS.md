# 音切れの診断ログ

起動時から自動で記録します。設定画面の **ログを開く** で保存先を開けます。
通常の保存先は `%LOCALAPPDATA%\GuitarSmartEffecter\logs` です。
`GUITAR_EFFECTER_DATA_DIR` を指定している場合は、その配下の `logs` です。

音切れが起きたら、おおよその発生時刻・その時の操作・出力先を控え、`audio*.jsonl` をまとめて共有してください。先に再起動してもログは追記されます。

- `audio.jsonl` が最新、`audio.1.jsonl` ～ `audio.3.jsonl` が過去のログです。1ファイル約4 MiBでローテーションし、合計約16 MiBまで保持します。
- 各行はJSONです。`unix_ms` はUTCのUnix時刻（ミリ秒）。`metrics` は接続中に約1秒間隔で保存します。
- メイン出力・自分用モニターの欠落／オーバーフロー、処理期限超過、最大処理時間、入出力ブロック数、クリップ数、ドライバー通知、マイクの一時欠落・待ち時間、推定遅延を記録します。
- `max_input_gap_us` / `max_output_gap_us` は接続開始以降のコールバック間隔の最大値です。Windowsのスケジューリングを含む参考値です。
- メイン入出力のエラーコードは 0=なし、1=Xrun、2=機器利用不可、3=権限拒否、4=ストリーム無効化、5=機器使用中、6=機器変更、7=リアルタイム優先度拒否、8=その他。マイクの詳細は `mic_error` を参照してください。
- 接続設定、機器名・識別子、エフェクト設定、ミュート／バイパス、メトロノームの状態も記録します。音声そのものは保存せず、外部へ自動送信しません。

音声コールバックではカウンター更新のみを行い、JSON化とファイル書き込みはワーカースレッドで処理します。保存に失敗すると設定画面にエラーを表示し、音声処理は継続します。

値は主に接続開始からの累積です。前後の差分で発生区間を確認してください。ログに異常が出なくても、USB機器内部・Windowsの下流・Discord側などで途切れる可能性があり、ログだけで全原因を断定することはできません。推定遅延は物理ループバックの実測ではありません。
